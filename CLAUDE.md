# BlogKub

www.blogkub.com is an Astro static site whose main product is a **client-side, no-code
Blogger theme builder**. A visitor assembles a theme from blocks in the browser and
downloads a Blogger XML file. Nothing is generated on a server, there is no backend, no
database, and no user accounts. The rest of the site is Thai and English documentation
that brings people to the builder.

The user is Thai and communicates in Thai. **Reply in Thai.** Code, comments, commit
messages and English site content stay in English.

## The builder: project/assets/builder-app.js

One file, one IIFE, no modules, no build step, no dependencies. It is loaded by
`builder.html` with a plain script tag. Know these pieces before editing.

### State

A single `S` object holds the whole project and is persisted to `localStorage` under
`bxb_project_v1`. Shape:

```
S = { name, templateId, design: {primary, accent, font, radius},
      seo: { title, desc, blogTitle, labelIndex, schema, og, orgType,
             logoUrl, favUrl, siteUrl, sameAs, schemaSoftwareApp, siteWww },
      blocks: [ { id, type, props, vis } ] }
```

`S` starts null. `startFromTemplate(id)` or the blank button builds it, then
`enterBuilder()` swaps the start screen for the editor. On load, a saved project is
resumed from `localStorage`. `window.BXBApp = { genXML, state }` is exposed at the very
end of the file, and is the entry point for testing.

### The pipeline that matters

- `LIB` (44 blocks), `IC` (inline SVG icons), `TEMPLATES` (8 themes), `SINGLETON_BLOCKS`
- `blockDefaults(type)`: a new block's initial props. **There are two copies**, one
  Thai and one English, chosen by `BL`. Change one, change the other.
- `renderBlockInner(b)`: canvas preview markup. Cosmetic only.
- `fieldsFor(b)`: the properties panel. Helpers: `txt`, `seg`, `tog`, `num`.
- `renderBlockStatic(b)`: **emits the Blogger XML. This is the real output.** A change
  that only fixes the canvas preview has not fixed anything.
- `genXML()`: assembles the whole theme, ordering blocks by `zoneOf(type)`.

### Two languages, two different variables

- `BL` is the **builder UI** language, from `localStorage.bxb_lang`. `tpl(th, en)` and
  `tr(s)` read it. Also decides which `blockDefaults` table is used.
- `S.lang` is the **generated blog's** language, emitted into the theme.

Do not confuse them. `docsUrl(slug)` follows `BL`, so an English user gets
`/en/learn/<slug>`. Never hardcode a help URL.

### Block placement

`genXML()` sorts blocks into zones rather than trusting list order:

```
0 announce   1 header   2 hero   4 content sections
6 related / morefrom / stories   7 notfound   8 footer   9 bottom utilities
```

Three blocks bypass this entirely. `toc`, `aeo`, and `breadcrumb` are injected **inline
into the post includable**, because `data:post.*` and `data:view.description` are only
in scope inside the post loop. Outside it they are undefined and the block renders empty.

`POST_BLOCKS` (postgrid, postlist, featured) mark where the Blog widget goes.
`UTIL_BOTTOM` blocks are floating or global UI and sort to the end.

### Page scoping

`condWrap(html, b)` wraps output in `<b:if>` from `b.vis.scope`:

| scope | condition |
| --- | --- |
| home | `data:view.isHomepage` |
| item | `data:view.isSingleItem` |
| page | `data:view.isPage` |
| label | `data:view.isLabelSearch` |

**`isSingleItem` is true on static pages as well as posts.** Use `data:view.isPost` when
you mean posts only. That distinction caused a real bug: the AEO summary box rendered as
an empty shell on About and Contact pages.

Blocks without a scope also get an explicit 404 exclusion, unless they are in
`SHOW_ON_ERROR` (header, footer, darkmode, notfound, themepicker, cookie, announce,
bookmark, backtotop, translate).

### Templates

Eight, all visible: `personal`, `travel`, `tech`, `sidebar-blog`, `magazine`, `company`,
`course`, `review`. `review` is the affiliate template and is the only one with the
product category menu.

`DEFAULT_UTILITIES` are pre-installed with every template: notfound, darkmode,
breadcrumb, readtime, toc, aeo, related, lightbox, anchorlink, backtotop, progress,
copycode. They self-place and self-hide, so they add value without cluttering the canvas.

## The site

Astro with `build.format: 'file'`, so `/about.html` serves `/about`. Around 100 pages.

Article pages are a single `.astro` file holding two template literals, `seo` and `body`,
passed to a layout:

```astro
---
import ArticleLayout from '../../layouts/ArticleLayout.astro';
const seo = `<title>...</title> ... <script type="application/ld+json">...</script>`;
const body = `<main class="wrap">...</main>`;
---
<ArticleLayout seo={seo}><Fragment set:html={body} /></ArticleLayout>
```

Older Thai articles use escaped double-quoted strings instead of backticks. Both work.
Prefer backticks for new files, and avoid backticks and `${` inside the content.

Every article carries the same JSON-LD graph: Person, Organization, WebSite,
BreadcrumbList, HowTo, TechArticle, FAQPage.

**The English learn hub is generated** from whatever exists in `dist/en/learn/`, so a new
English article appears automatically. **The Thai learn hub is a hand-maintained static
file** at `project/learn/index.html`. A new Thai article that is not added there is
reachable only by direct URL. That has already happened once, to `label-indexing`.

## Build and deploy

```
prebuild   sync-public.mjs         copy ./project into site/public
build      astro build
postbuild  build-en-learn-hub -> build-hreflang -> build-feeds
           -> build-sitemaps -> indexnow-plan
```

Push to `main` triggers `.github/workflows/deploy.yml`: build, deploy through
`cloudflare/wrangler-action`, then submit to IndexNow. **That workflow is the only thing
that builds and deploys this site.** Keep it that way.

### Why there is exactly one build path

There used to be three builds and two racing deploys per push:

1. the workflow's own build step
2. `wrangler deploy` re-running `build.command` from `wrangler.jsonc`
3. Cloudflare building the repo through its own Git integration

Builds 2 and 3 were removed. The reason is one failure mode: the postbuild chain includes
the IndexNow planner, which decides what to announce by fetching the previously deployed
`indexnow-state.json` from the live site. Any planner run between the plan step and the
submit step can overwrite the queue, and any deploy that lands early can publish a state
file that makes the next planner run conclude nothing changed. Either way the submit step
announces nothing and still reports success.

**Before adding anything to postbuild, ask what happens when it runs twice, the second
time against a site that has not been updated yet.**

Do not restore `build` to `wrangler.jsonc` and do not reconnect Cloudflare's Git
integration.

## IndexNow

- `indexnow-plan.mjs` hashes every built page, fetches previous hashes from
  `https://www.blogkub.com/indexnow-state.json`, and queues only what changed. The
  sitemap cannot answer this, because its `<lastmod>` is the build date. Unreachable
  state means "first run", so everything is queued.
- `indexnow-submit.mjs` verifies the key file is live before POSTing and aborts if not.
  200 and 202 are both success; 202 means key validation is still pending.
- A forced run (`npm run indexnow:all`) writes `.indexnow-queue-all.json`, a name the
  ordinary path never writes, so a rebuild cannot clobber it. The submitter prefers it
  when present and deletes it only after every batch is accepted.
- Both sitemaps are added by hand, since they never appear in `sitemap.xml`'s own `<loc>`
  list. Note that `sitemap-images.xml` includes any page with an on-domain image, and the
  author box counts, so most articles are in it.
- **Do not run a forced resubmission casually.** Repeatedly announcing unchanged URLs
  looks like spam. It has already been run twice.

A healthy ordinary deploy looks like `indexnow: 8 changed of 108 pages queued`. If a
content change reports 0, or a trivial change reports everything, something is wrong.

## Conventions

- **No personal data in generated themes.** No verification keys, IndexNow keys,
  affiliate IDs, or personally hosted image URLs may be baked into the builder's output.
  The user asked for this explicitly.
- **English site content contains no em dash and no middot.** Thai pages are
  unrestricted. English pages use `&nbsp;` as the meta separator and `(Ben)` rather than
  a middot. Arrows are the literal character, as in `Theme -> three-dot menu ->
  Backup/Restore`.
- **Keep this file pure ASCII.** It gets copied through mobile clients that mangle
  anything above U+007F. Em dashes in an earlier version came back as `<mojibake>` in 11
  places.
- **The public contact address is hello@blogkub.com.** Never publish the owner's personal
  email.
- Builder help links go through `docsUrl(slug)`.
- Never put the model identifier in commits, PR titles or bodies, code comments, or
  anything else pushed to the repo.

## Testing without a browser

There is no test runner and no CI tests. The loop that has actually caught bugs:

1. `node --check` on anything edited
2. boot `project/builder.html` in **jsdom**, then inject `builder-app.js` by hand,
   because jsdom will not fetch the external bundle
3. start a project the way a user would: click `#startGrid .tpl-card`
4. call `window.BXBApp.genXML()` and assert on the exported XML
5. for runtime behaviour, extract the emitted CDATA scripts and drive them against a
   simulated Blogger DOM with a stubbed `fetch`

Skeleton that works:

```js
const dom = new JSDOM(readFileSync('project/builder.html', 'utf8'),
  { url: 'https://www.blogkub.com/builder.html', runScripts: 'dangerously',
    virtualConsole: new VirtualConsole(), pretendToBeVisual: true });
const el = dom.window.document.createElement('script');
el.textContent = readFileSync('project/assets/builder-app.js', 'utf8');
dom.window.document.body.appendChild(el);
dom.window.document.querySelector('#startGrid .tpl-card[data-tpl="review"]').click();
const xml = dom.window.BXBApp.genXML();
```

Install jsdom temporarily under `site/`, run the test from `site/` so the import
resolves, then uninstall it and `git checkout -- site/package-lock.json` so only intended
files appear in `git status`.

**Reproduce a reported bug on the pre-fix code with `git stash` before claiming a fix.**
Every real bug here has been confirmed that way, and the ones that looked obvious were
usually caused by something else.

## Gotchas that have already bitten

- **`isSingleItem` includes pages.** See the scoping table above.
- **CSS specificity.** The theme's own `.site-nav ul` (0,1,1) beat `.rv-cat-list` (0,1,0)
  and rendered a dropdown horizontally. Scope new selectors with two classes.
- **A `<button>` does not inherit `a { color }`.** A category button rendered black for
  exactly this reason.
- **A bare `<span>` ignores width and height.** Story rings rendered as ellipses until
  `display:block` and `aspect-ratio:1` were added.
- **`object-fit: cover` crops.** The story viewer sliced landscape photos into a 9:16
  slot. Fixed with `contain` plus a blurred copy of the same image behind it.
- **robots.txt outranks meta robots.** A blanket `Disallow: /search` silently defeated
  the label-indexing feature no matter what the meta tag said.
- **`ArticleLayout.astro` hardcodes `href="/en/"`** in the header and the mobile drawer.
  `build-hreflang.mjs` rewrites it per page at build time. Fix language-switch bugs
  there, not in 44 separate articles.
- **Panels mirroring one setting in two places** must call `renderProps()` as well as
  their own re-render, or the mirrored control lags a refresh behind.
- **`blockDefaults` exists twice**, Thai and English.
- **Blogger page URLs come from the title at first publish** and keep only Latin letters
  and digits, so an all-Thai title yields `blog-page.html` and cannot be changed. Pages
  have no custom permalink field. This is documented at `/learn/create-page`.

## Environment

The remote container is ephemeral and can be reset mid-session, taking the working tree
with it. Anything not pushed is lost. The repo is public, so `git fetch` and
`raw.githubusercontent.com` work unauthenticated, but pushing needs a credential, and
editing `.github/workflows/` needs `workflow` scope on top of `repo`.

When a push is blocked, park the file under `ops/` and ask the user to apply it through
the GitHub web editor. That is how the current `deploy.yml` was installed.

Commits are signed, but this container has no `ssh-keygen`, so `git log %G?` reports `N`,
meaning "cannot verify", not "unsigned". GitHub shows them as Verified. Do not try to
fix this by configuring `gpg.ssh.allowedSignersFile`: it turns `N` into `B`, which is
worse, and there is no verifier to make it work.
